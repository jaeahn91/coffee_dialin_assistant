# AI Coffee Dial-in Assistant

원두 봉지의 QR을 찍으면 로스터가 등록한 추천 레시피가 나오고, 맛 피드백을 입력하면 다음 추출에서 시도할 조정값을 돌려주는 서비스의 설계 문서. 쌓이는 원두-레시피-피드백 데이터는 로스터에게 돌아간다.

## 어떤 문제를 푸는가

스페셜티 로스터의 고객은 같은 원두를 사도 자기 장비와 환경에서는 추천 레시피대로 맛이 나오지 않는 경우가 많다. 고객은 원두를 의심하고, 로스터는 어떤 고객이 어떤 원두에서 무엇을 겪는지 알 길이 없다. 이 간극을 추출 피드백 루프로 메운다.

이 문제 정의는 6년 넘게 거의 매일 아침 핸드드립으로 커피를 내려 온 홈카페 유저로서의 경험과 업계 사람들과의 대화에서 출발했다. 기획자 자신이 14개월간 175회의 추출에서 투입량·분쇄도·푸어 구조·추출 시간을 기록해 봤지만 파라미터만 쌓이고 맛 평가라는 결과 피드백은 닫히지 않았다. 그 한계가 이 서비스의 원형이다. 기록 원본은 [data/brew_log_raw_2022-2023.md](data/brew_log_raw_2022-2023.md)에 정제하지 않고 그대로 올려 두었다. 조정 규칙의 수위 같은 설계 결정에는 파일럿 후보 로스터리 대표의 현장 피드백이 반영되어 있다.

핵심 가설: 피드백 한 번이 실제로 다음 잔을 더 낫게 만든다. 검증 지표와 잠정 기준은 PRD §2에 있다.

## 결정된 것 / 열려 있는 것

결정 (각 버전의 변경 요약이 해당 PRD 상단에 있다):

- 멀티 테넌트 구조 — QR 접속은 로스터별 페이지로, 데이터는 테넌트 키로 격리 (§3-1, §8-4)
- 피드백 입력 흐름 — 3지선다 2회를 9칸 격자에 매핑, 추출시간 이탈 시 물온도 분기 트리 (§5, §6)
- 조정 규칙의 거울상 불변식 정의와 전수 검증 (§6-3)
- 데이터 모델 v0 — 9개 엔티티, 조정 이력 포함 (§8)
- QR 발급 단위 — 봉지 단위 유니크 발급, 세션 연속성의 전제 (§8-3)
- 핵심 가설의 측정 지표 — 조정 후 만족도 상승률, 잠정 숫자 기준 포함 (§2)

열려 있는 것 (대표):

- 조정 폭과 감쇠 규칙의 수치 (부록 5)
- 분쇄도 표현 방식 (부록 7)
- 레시피 등록 UX, 주간 산출물 형식 (부록 8)
- 전체 목록은 PRD 부록 "미결정 항목 모음"

## 설계 원칙

- 미결정을 숨기지 않는다. 본문에는 `[미결정]` 표기, 부록에는 번호 목록으로 관리하고, 결정되면 취소선과 결정 버전을 남긴다.
- 채워진 칸도 확정이 아니라 검증 대상이다. 조정 규칙은 거울상 불변식(모든 방향성 처방에 역방향 경로가 존재해야 한다)으로 전수 검증했다.
- AI 호출에는 경계를 둔다. 규칙으로 끝나는 경로에서는 호출이 없고, 격자로 못 잡는 케이스만 챗봇이 받는다 (§9).
- 설계·요건 정의·검증은 직접 하고, 구현 단계의 코드 작성은 AI를 도구로 쓴다.

## 저장소 구조

```
docs/    # PRD 및 설계 문서 (버전별 파일 보존)
data/    # 기획의 출발점이 된 개인 추출 기록 원본 (2022–2023, 175회)
```

코드 작업이 시작되면 `src/` 등을 추가한다. 구조는 필요해질 때 바꾼다.

## 문서 규칙

- PRD는 버전별로 새 파일을 만들어 이전 버전을 보존한다 (`_vX.Y.md`).
- 버전 간 변경 요약은 새 버전 문서 상단에 둔다.
- 미결정 항목은 문서 내 `[미결정]` 표기 + 부록의 미결정 목록으로 관리한다.
