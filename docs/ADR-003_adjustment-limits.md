# ADR-003: 조정 경계 가드 — 절대 한계 + 분쇄 반복 상한

- 날짜: 2026-07-03
- 상태: 승인·구현됨
- 관련: ADR-001(쓰기 경로), ADR-002(분쇄도 표현), PRD v0.3 §6-3(수렴 조건)·부록5(조정 폭)

## 트리거

파일럿 실데이터(2026-07-02~03)에서 같은 QR로 '아쉬워요→진해요→짧아요'가 반복되며 온도가
93→92→91→90으로 **단조 하강**하는 것을 관찰. `applyMoves`에 절대 한계가 없어 같은 답이
반복되면 무한정 진행된다. §6-3의 수렴 장치(반전 감지 감쇠)는 핑퐁 진동(A→B→A)용이라
단조 하강에는 무력 — 별도의 안전망이 필요하다.

## 결정

1. **물온도: 절대 80~100°C 클램프.** 100°C는 끓는점(물리적으로 그 위가 없음), 80°C 미만
   핫브루는 실질 무의미. 스텝이 경계를 넘으면 경계값까지만 적용(부분 클램프 = 채택),
   이미 경계에 있으면 그 move를 무효화한다.
2. **물량: 스텝을 절대 g에서 원두량 비례로 변경.** standard 1스텝 = 원두량 × 0.5
   → 비율(물/원두)이 0.5씩 움직인다(1:15 → 1:15.5). 절대 g는 레시피마다 의미가 달라지기
   때문(도징 미상 레시피만 기존 5/10g 폴백). 경계 = **기준(활성 레시피) 물량 ±20%** —
   비율이라 원두별 레시피 차이에 자동 대응.
3. **분쇄도: 같은 방향 권유 연속 3회 상한(횟수 근사).** 분쇄도는 수치 추적이 없어(ADR-002
   권유 이력 결정, §6-4 표현 미결정) µm 경계를 직접 강제할 수 없다. 대신 사슬(§8-5)에서
   같은 방향 분쇄 권유가 3회 연속이면 4회째부터 무효화한다.
   - **런 정의**: 분쇄가 아닌 조정(온도·물량)은 런을 끊지 않는다 — 그라인더 위치는 그대로다.
     반대 방향 분쇄 권유만 런을 리셋한다.
   - 설계 의도상의 물리 경계(µm 추적 도입 시): 하한 에스프레소(~300µm), 상한 2000µm
     (테츠 카스야 신 레시피의 1400~1500µm 감안).
4. **도달 시 행동: 해당 변수 move만 무효화, 처방의 나머지 move는 그대로.** 챗봇으로 넘기지
   않는다 — 반복성 동작에 AI 비용을 쓰지 않는다(§9 경계 유지). 대신 고정 문구(§9 템플릿,
   `LIMIT_NOTICES`): "○○는 이미 충분히 조정했어요. 그래도 아쉬우면 로스터리에 문의해 주세요."
   모든 move가 무효화되면 결과 화면 헤딩을 "자동 조정이 한계에 닿았어요"로 바꾼다.
5. **기록: `adjustment.moves`에는 채택된 move만 저장.** 무효화된 move는 저장하지 않는다 —
   `rule_source`가 있으니 발화 규칙의 기대 moves와의 차이로 사후 도출 가능(스키마 변경 회피).
   전부 무효화된 조정도 행으로 남는다(moves=[], before==after) — 피드백이 있었다는 사실과
   사슬 연속성을 보존한다.

## 성격

이 가드는 **수렴 장치가 아니라 "터무니없는 처방" 방지 안전망**이다. 기준 93°C에서 하한까지
slight 스텝으로 13회 — 정상 사용에선 닿지 않는다. 수렴 수치(감쇠, 목표 구간 폭 vs 스텝 폭)는
부록5 미결정으로 유지하고 파일럿 데이터로 확정한다.

## 거울상 불변식(§6-3)과의 관계

경계는 한 방향만 막고 **역방향은 항상 허용**된다(분쇄 런도 반대 방향 권유는 즉시 허용+리셋).
따라서 모든 방향성 처방의 역방향 경로는 유지된다. temp reset은 기준점 복귀형이라 경계와 무관.

## 알려진 한계 (파일럿 감수)

- 분쇄 런 검사는 기록 시점의 이력 조회(TS) — 동시 세션 레이스에서 1회 더 허용될 수 있다.
  강제 지점을 RPC로 내리면 없앨 수 있으나 파일럿 규모에서 불필요.
- 무효화된 조정은 재스캔 카드에 흔적이 없다(문구는 피드백 직후 화면에만). 필요해지면
  latest_adjustment 표시에 병기 검토.
- 이력 조회 깊이 10 — 분쇄 아닌 조정만 10회 이상 연속되는 극단에선 런이 과소평가될 수
  있으나, 그 경우 온도·물량 자체 경계가 먼저 잡는다.
- 결과 화면은 클라이언트 계산을 먼저 보여주고 서버 확정본 도착 시 갈아끼운다 — 가드가
  발동하는 드문 경우에만 문구가 한 박자 늦게 나타난다.

## 구현

- `lib/config/adjustment-limits.ts` — 경계 노브(80/100, ±20%, 런 3, 이력 깊이 10)
- `lib/config/adjustment-steps.ts` — 물 비례 스텝(`WATER_STEP_DOSE_RATIO`) + 폴백
- `lib/server/derive.ts` — `applyMoves`가 `GuardedApply`(채택 moves + limited) 반환,
  `trailingGrindRun` 런 계산
- `lib/domain/describe.ts` — `LIMIT_NOTICES` 고정 문구(`describe.test.ts`로 §9 잠금)
- `supabase/migrations/0004_adjustment_limits.sql` — `recent_moves_for_qr` 읽기 RPC
  (0002·0003과 같은 사슬 논리), `lib/db/adjustments.ts` 슬라이스
- 검증: 유닛 테스트 14개 추가(경계·부분 클램프·런 의미론), Playwright 실주행 —
  일회용 QR로 sour/medium(분쇄 곱게 단독) 4회 완주, 4회째 가드 발동·moves=[] 기록·
  고정 문구 표시 확인 후 테스트 데이터 cascade 삭제.
