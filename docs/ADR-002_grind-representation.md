# ADR-002: 분쇄도는 수정값이 아니라 권유 이력으로 표시한다 (+µm 병기, 언스페셜티 링크)

날짜: 2026-07-02 · 상태: 채택 · 관련: PRD §6-4, 부록 7, ADR-001

## 결정

재스캔 시 조정 반영 레시피를 표시할 때:

1. **물량·물온도·도징은 조정된 절대값으로 표시한다** — after_snapshot 기준, 기준값 병기
   (예: `물 260g (기준 250g)`).
2. **분쇄도는 수치를 수정해서 보여주지 않는다.** 기준 표기를 유지하고, 직전 조정의
   솔루션 전체(모든 move)를 §9 템플릿 한 줄로 보여준다
   (예: `최근 솔루션: 분쇄도를 곱게 + 물을 늘리기`). 물·온도는 숫자에도 반영되지만
   이 줄이 "왜 바뀌었는지"의 설명을 겸한다. (2026-07-02 수정: 분쇄 move만 →
   전체 move — "최근 솔루션" 문구가 일부만 보여주면 오해의 소지)
3. 기준 레시피에 **µm를 선택 병기**한다 — `recipe.grind_um`(nullable), 표시는
   `분쇄 코만단테 22클릭 (약 700µm)`. 로스터가 모르면 비워 두고 표시를 생략한다.
4. **언스페셜티 분쇄도 나침반 링크**를 레시피 카드에 둔다(새 탭). 사진 실측 도구라
   그라인더 모델과 무관하게 손님이 자기 분쇄도(µm)를 측정·비교할 수 있다.
   URL은 `lib/config/links.ts`에서 관리(외부 의존 차단/교체 지점).

## 근거

- **자기교정 비대칭**: 물량·온도는 저울·주전자로 절대값을 그대로 실행할 수 있어
  지난 권유를 따랐는지와 무관하게 표시값이 곧 지시가 된다(자기교정적). 분쇄도는
  손님 그라인더가 참조 그라인더와 다르면 절대값이 해석 불가능하고, 상대 지시만
  실행 가능한데 상대 지시는 관측 불가능한 손님의 이전 상태에 의존한다.
- **준수 관측 불가**: 분쇄 권유를 따랐는지 알 수 없는 상태에서 절대값을 수정해
  보여주면 알 수 없는 기준선 위에 가짜 정밀도를 얹게 된다.
- **µm 병기가 유효해진 이유**: 언스페셜티 나침반이 사진 실측(입자 인식, 평균/표준편차)
  으로 µm를 제공하므로, 의지 있는 손님에게 µm는 어떤 그라인더에서도 검증 가능한
  절대 기준점이 된다. 로스터도 같은 도구로 자기 기준 분쇄도를 실측해 입력할 수 있다.

## 기각한 대안

- **µm 정준화 + 그라인더 변환표 즉시 도입**: 변환표는 등록된 그라인더만, 버 마모·정렬
  편차만큼 부정확하게 커버한다. 조정 표시에는 불필요(이력 표시로 충분)하고, 입력
  규격화는 µm 선택 병기로 달성된다.
- **분쇄도도 수치 조정 표시**: 위 근거로 기각. `applyMoves`가 분쇄를 수치 적용하지
  않는 것은 ADR-001의 "알려진 한계"였으나 본 결정으로 설계로 승격.

## 사슬 누적 (이 결정이 강제한 수정)

조정 레시피를 표시하는 순간 손님은 조정값으로 추출하므로, 다음 조정의
before_snapshot은 기준 레시피가 아니라 **그 세션이 이은 직전 조정의 after_snapshot**
이어야 한다(§8-5 "after_snapshot = 다음 세션의 표시 레시피"). 화면 표시와 사슬 연결이
같은 조정을 가리키도록, 표시용 조회는 `latest_adjustment_for_qr`(0003) —
`start_brew_session`의 사슬 연결 쿼리와 동일 논리 — 를 쓴다.

## 이연된 결정

| 결정 | 트리거 |
|---|---|
| 조정 후 µm 목표 병기 (예: "조금 곱게 (약 -30µm)") | 파일럿 로스터 피드백 |
| 나침반 딥링크·정식 연동 | 언스페셜티 측 API/파라미터 제공 시 |
| 손님 그라인더 단위 변환 (부록 7 본체) | 손님 측 그라인더 정보를 받게 되는 시점 |
| §9 템플릿에 참조 그라인더 힌트("1~2클릭") 추가 | 파일럿 로스터 피드백 |
